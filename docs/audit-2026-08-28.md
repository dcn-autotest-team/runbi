## 🔴 P0 — 必修（影响核心体验/安全）

### 1.［功能］mouse_hook.rs：双击/拖窗口 = 假划词洪水
- 位置：`desktop/src-tauri/src/commands/mouse_hook.rs:157-175`
- 问题：触发条件只是「位移>6px + 按住>60ms」或「350ms 内二次单击」，grab 后不校验剪贴板是否真的被注入的 Ctrl+C 改变 → 双击任意按钮/图标、拖动任意窗口标题栏都会触发，弹窗内容是**旧剪贴板残留文本**
- 修复：grab 序列末尾若 `captured_text == original_clip`（剪贴板未变化 = 没有新选中内容）直接 return，不弹窗

### 2.［功能］双触发竞态：一次划词可能弹两次窗 + 双倍 LLM 调用
- 位置：`desktop/src-tauri/src/commands/replacer.rs:100,106`（唯二置位处）
- 问题：只有 `replace_text` 会置 `is_internal_action=true`；`mouse_hook.rs` 的 grab 和 `main.rs` 快捷键路径注入 Ctrl+C 时**没有置位** → 500ms 轮询的 clipboard_monitor 有概率在 ~80ms 剪贴板窗口内捕获同一段文本 → 双弹窗 + 重复生成
- 修复：两处 grab 序列开始时置位、结束时清零（照抄 replacer.rs 的模式）

### 3.［安全/隐私］clipboard_monitor 会吞密码
- 位置：`desktop/src-tauri/src/commands/clipboard_monitor.rs`（轮询主体）
- 问题：密码管理器「复制密码」→ 500ms 内被读走 → 明文显示在浮窗并自动发给 LLM endpoint
- 修复（组合拳）：剪贴板触发默认 opt-in；高熵字符串启发式（UUID/32-64 位随机串不弹窗）；前台进程黑名单（keepass/1password/bitwarden 等进程名不触发）

### 4.［功能/扩展］扩展端 endpoint 拼接 404 bug 没同步修
- 位置：`src/adapters/ChromePortLLMTransport.ts:266`、`src/background/streamHandler.ts:62,251`
- 问题：三处都是盲目拼接 `baseUrl + '/chat/completions'` → 用户保存完整 endpoint（以 /chat/completions 结尾）时路径翻倍 → 404。桌面端 `desktop/src/adapters/TauriIPCLLMTransport.ts` 的 `resolveEndpoint()` 已修，扩展端漏同步
- 修复：三处统一加「已以 /chat/completions 结尾则不再拼接」判断（可直接复用/复制 resolveEndpoint 实现）

## 🟠 P1 — 重要

### 5.［功能］replacer.rs 剪贴板恢复竞态 + 非文本剪贴板丢失
- 位置：`desktop/src-tauri/src/commands/replacer.rs:149-170`
- 问题：Ctrl+V 后固定 sleep 100ms 就恢复原剪贴板——大文本/慢应用可能还没完成粘贴；且原剪贴板为图片/文件时只备份了文本（read_text），原内容直接丢失
- 修复：用剪贴板序列号（GetClipboardSequenceNumber）轮询验证粘贴应用已读取后再恢复；非文本场景不覆盖并提示

### 6.［易用］置顶状态与窗口实际状态不同步
- 位置：`desktop/src-tauri/tauri.conf.json`（`alwaysOnTop: true`）vs `desktop/src/App.tsx`（isPinned 初始 false）
- 问题：启动时窗口实际置顶，但 UI 显示未置顶；Esc 可隐藏 → 行为拧巴
- 修复：二选一——config 改 false，或前端 isPinned 初始化为 true（推荐后者，浮窗工具默认置顶合理）

### 7.［易用］Tab 键劫持与 reply 场景冲突
- 位置：`desktop/src/App.tsx` 键盘 useEffect（Tab → STYLE_ORDER 循环）+ 底部提示条
- 问题：提示「Tab 切换风格」，但 reply 模式下风格选择器已隐藏（PolishPanel `activeStyle !== 'reply' &&`）→ Tab 仍切换风格且无任何可见 UI 反馈；同时劫持了无障碍焦点导航
- 修复：reply 模式下不劫持 Tab（或仅在当前可见风格间循环）；提示条文案同步

### 8.［功能］视觉降级重试会叠加残文本
- 位置：`desktop/src/App.tsx` handleStartPolish 的 onError fallback（`runStream(textOnlyConfig)`）
- 问题：vision 流失败前已收到的部分 chunk 没清空，与重试输出拼接 → 生成结果前半截错乱
- 修复：降级重试前 `setPolishedText('')`

### 9.［安全］API Key 明文存储 + endpoint 不限协议
- 位置：`desktop/src/App.tsx`（localStorage 存 apiKey）、扩展 `ChromeStorageProvider`
- 问题：key 明文落盘（WebView2 leveldb）；endpoint 接受 `http://` → key+正文+截图明文传输
- 修复：最少做 https 前缀校验/警告；进阶用 keyring crate（OS 凭据库）存 key

### 10.［隐私/数据最小化］截图过度捕获
- 位置：`desktop/src-tauri/src/main.rs`（快捷键路径）、`mouse_hook.rs:173`
- 问题：只要划词成功就截取前台窗口全图并广播到前端存 state，即使最终走润色模式根本不用图
- 修复：Rust 侧仅当窗口标题/进程匹配会话类应用时截图，或改为前端 classifyContext 判定 reply 后再主动 invoke `capture_foreground_screenshot`

### 11.［性能］clipboard_monitor 500ms 轮询
- 位置：`desktop/src-tauri/src/commands/clipboard_monitor.rs`
- 问题：永久 500ms 轮询浪费电量，也是 P0-2 竞态的温床
- 修复：改用 Win32 `AddClipboardFormatListener`（WM_CLIPBOARDUPDATE）事件驱动

### 12.［功能］position.rs 多显示器坐标错位
- 位置：`desktop/src-tauri/src/commands/position.rs`（position_window_at_cursor）
- 问题：只用了 `work_area().size` 没用 origin（position）→ 副屏（尤其负坐标）时 clamp 到主屏范围，窗口飞走
- 修复：cursor 与窗口坐标统一转为相对当前 monitor 原点的坐标系再 clamp，最后加回 origin

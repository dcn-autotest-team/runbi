# 重设计：润色面板"方式选择"统一化

> 2026-08-30 · 背景：内置话术库与专家提示词上线后，面板同时存在四套选择机制，用户心智负担过重。本文档记录产品分析、重设计方案、实现与实测结论。

## 1. 问题定义

改版后的润色面板同时呈现四种"影响输出"的入口：

| # | 入口 | 职责 | 问题 |
|---|------|------|------|
| 1 | 润色方式下拉（7 风格） | 选择"怎么改"的写作人格 | 与 #2、#3 职责重叠 |
| 2 | 「🧑‍💼 专家」按钮 + 专家角标 | 同样是"谁来改"的人格（277 位） | 与 #1 互斥却同时呈现；专家生效时风格下拉仍显示，选择结果互相覆盖，用户无从判断谁在生效 |
| 3 | 润色快捷标签（自然流畅/大幅精简/专业商务/提炼要点/文采润色） | 对输出的一句话指令 | 与 #1 近 100% 重叠：专业商务≈职场商务、大幅精简≈精简提炼、文采润色≈文采飞扬、自然流畅≈通用润色 |
| 4 | 「📚 话术库」按钮 | 查参考话术模板（独立任务） | 无重复，但夹在 #2/#3 之间加剧拥挤 |

**核心判断**：#1、#2、#3 回答的是同一个问题——"这段文字按什么标准处理"。三个入口回答一个问题 = 心智负担三倍。#4 回答的是另一个问题（"有没有现成参考素材"），应当保留。

## 2. 设计原则

1. **一个问题只留一个入口**：风格与专家合并为同一个"方式"槽位，互斥生效，状态唯一可见。
2. **默认路径零装饰**：80% 场景只润色，界面只出现风格下拉；专家、并行是进阶能力，收进下拉深处。
3. **删除优于收纳**：与风格重复的快捷标签直接删除，而不是挪个位置。
4. **不重复的不动**：话术库是独立任务，保留独立入口；回复模式的语气标签服务"起草回复"这一不同任务，保留。

## 3. 方案

### 3.1 统一"方式"下拉（StyleTabs 扩展）

- 触发器：无专家时显示风格名（原样）；专家生效时显示 `emoji + 专家名`（teal 高亮态），行标签变为「处理方式 · 专家」。
- 菜单结构（自上而下）：
  1. 专家生效时：置顶专家条目（高亮）+ 「✕ 清除专家，返回风格模式」
  2. 7 个风格（专家生效时全部呈非选中态）
  3. 分隔线 + 「🧑‍💼 打开专家库…」（打开原专家选择弹窗：搜索/分类/预览/单选应用/多选并行）
- 互斥规则：**点任意风格 = 清除专家并应用风格**；专家只在专家库内选择产生。

### 3.2 删除润色快捷标签

- 润色模式不再渲染任何快捷标签（POLISH_QUICK_TAGS 移除），输入框占位符改为「补充要求（可选）：语气、格式、重点…回车应用」。
- 回复模式保留原有标签体系（上下文意图 chips + 行业意图 + 自定义指令），因其职责是"起草回复的语气/意图"，与风格下拉不重叠。

### 3.3 保留项

- 「📚 话术库」：独立任务，保留为工具行唯一按钮。
- 专家多选并行对比：入口随专家库迁移，交互不变。

### 3.4 顺带修复的既有缺陷

- **被困回复模式**：原逻辑 `activeStyle !== 'reply'` 才渲染风格下拉——默认风格恰为"智能回复"的用户没有任何切回润色的入口。改为 `!screenReplyAnalysis` 时渲染（屏幕分析上下文内仍隐藏，避免干扰视觉分析流程）。

## 4. 改动清单

| 文件 | 改动 |
|---|---|
| `shared/components/StyleTabs.tsx` | 新增 `expert` / `onClearExpert` / `onOpenExperts` props；触发器与菜单按 3.1 渲染 |
| `shared/components/PolishPanel.tsx` | 移除专家按钮与专家角标；工具行仅剩话术库；润色模式删除快捷标签；下拉显示条件改为 `!screenReplyAnalysis` |
| `desktop/src/App.tsx` | `handleStyleChange` 先清除专家再应用风格；向 PolishPanel 传递统一后的 props |

兼容性：新增 props 均可选，Chrome 扩展端（未传新 props）行为不变、不受影响。

## 5. 验证记录（实机，tauri dev + 真实鼠标事件）

| 用例 | 结果 |
|---|---|

| 下拉内 7 风格 + 分隔线 + 打开专家库… | ✓ |
| 选「通用润色」→ 触发器更新、即时重新生成 | ✓ |

| 专家生效时开下拉：专家置顶高亮 + 清除按钮，7 风格均非选中态 | ✓ |

| 回复模式：语气标签保留 | ✓ |
| 静态验证：tsc ×2、vitest 673/673、双端 vite build | ✓ |

## 6. 取舍与遗留建议

- **专家在回复模式不可达**（屏幕分析上下文内下拉隐藏）：有意为之——回复模式有自己的语气指令体系，混入"写作人格"会重新制造选择过载。若后续数据表明需求强，可在回复 refine 标签尾部加「专家语气…」单一入口。
- **并行对比的发现成本**提高（藏在专家库内）：符合"进阶能力深收"原则；若使用率高，可在专家库顶部加「最近并行」快捷组。
- **设置页的"人设偏好"与面板"专家"仍存在概念相邻**：前者是"我是什么人"（语气人设），后者是"谁来处理"（领域专家），语义可区分，暂不合并；建议在设置项描述里强调这一区分。
- 埋点建议：统计统一下拉内 风格切换 / 专家库打开 / 专家应用 / 并行对比 四个动作的转化，验证合并没有损伤专家功能的使用率。

# 迭代 2：AI 自动决策默认化（降低使用门槛）

> 用户反馈："整体界面还是有点不会用，过于复杂了。能用 AI 做的或 AI 辅助决策的，让 AI 来做而不是人。"

## 1. 问题定义

迭代 1 解决了"入口重复"，但没解决"决策负担"：用户仍需回答三个本应由 AI 回答的问题——

| 用户被要求做的决策 | 位置 | 为什么不该问用户 |
|---|---|---|
| 选哪种润色方式（7 风格 + 277 专家） | 面板下拉 | 划词内容 + 窗口标题已经隐含答案（聊天→回复、论文→学术、代码→精简） |
| 选哪个行业模板包 | 设置页 | "微商/律所/房产保险"是场景属性，窗口标题和文字可直接推断；且用户不理解"模板包"与面板的关系 |
| 选什么人设语气 | 设置页 | 对话语气应跟随对方与语境（回复铁律已有此规则），预设人设是少数派需求 |

更深层的问题：设置页的「行业模板包 / 人设偏好」与主界面**完全断开**——用户配了不知道在哪生效，不配也不知道缺了什么。

## 2. 设计原则

1. **AI 决策，人只否决**：默认状态下 AI 替用户做所有可选决策，并把决策结果"可见化"（触发器、标签、toast），用户只在不满时才需要出手。
2. **显式选择永远覆盖 AI**：用户一旦手动选了风格/行业/人设，AI 不再越权。
3. **设置项解释"怎么串起来"**：每个设置项说明它在界面何处自动生效。

## 3. 方案与实现

### 3.1 智能模式（面板默认方式）

- 统一下拉第一项「✨ 智能模式」，**默认选中**；触发器显示「✨ 智能」，行标签「润色方式 · AI 自动」。
- 生效逻辑：划词时运行既有 `classifyContext`（文字 + 来源应用 + 窗口标题 → 7 风格之一），置信度 ≥0.7 时 toast 告知"AI 识别为【X】(原因)"。
- 点任意具体风格 → 退出智能模式并记住（`autoMode` 持久化）；点「✨ 智能模式」→ 回到 AI 决策并立即按当前文本重新生成。

### 3.2 行业智能识别（设置默认项）

- `INDUSTRY_PACKS` 新增首项「✨ 智能识别 (推荐)」并成为默认值；三个真实行业包各自携带 `autoKeywords` 关键词组。
- 每次生成实时运行 `detectIndustryPack(窗口标题 + 选中文本)`：命中即注入该包的场景规则与意图 chips，未命中自动通用。**划词和智能回复时自动生效**——命中行业的回复面板会自动出现该行业的专属快捷按钮（这就是与界面的串联点）。
- 迁移：旧默认 `general` 自动视为 `auto`；用户显式选过的行业包保持不变。

### 3.3 人设智能跟随（语义澄清）

- 默认人设改名「✨ 智能跟随 (推荐)：AI 根据对话语境自动匹配语气，无需设置」——行为与原"标准"一致（不注入固定人设，由回复铁律驱动"语气跟对方走"），但把"不配置 = AI 在管"这一点说清楚。
- 用户显式选择的人设（如"亲切亲和"）照旧覆盖，生成时自动带上，无需每次选择。

### 3.4 设置页降噪

- 「自定义回复指令」折叠为 `<details>` 高级项，摘要显示「已定义 N 个 / 未设置，AI 默认已覆盖常见场景」。
- 行业包与人设两个设置项各加一行"生效方式"说明（划词时自动生效、命中行业出现专属按钮等），把设置与界面的连接讲明白。

## 5. 验证记录

- 单测：新增 5 用例（电商关键词→微商包、法律→律所包、保险→房产保险包、无命中→null 回退、auto 默认项存在），全量 678/678 通过。
- 实机（全新实例，默认零配置）：面板显示「润色方式 · AI 自动」+「✨ 智能」高亮触发器；设置页行业包=智能识别(推荐)、人设=用户已有显式选择(亲切亲和，保留)、自定义指令折叠为「已定义 2 个」；tsc ×2 与双端 build 通过。

## 6. 用户旅程（改版后）

**默认路径（零决策）**：划词 → AI 自动判风格（toast 说明）→ 生成；聊天场景 AI 自动带行业规则与意图按钮（badge 可见）。用户全程无需理解"风格/行业包/人设"任何概念。

**进阶路径（可选否决）**：对 AI 的判断不满意 → 下拉里点一个具体风格 / 进专家库选人格 / 并行对比；设置页可锁定行业包与人设。AI 的每次决策都可被看见、可被否决、否决后被记住。

# 迭代 3：模式可见化与话术库衔接（信息架构定稿）

> 用户反馈："我怎么知道我当前处于什么模式？模板库怎么跟他们衔接？润色模式和回复模式逻辑混乱。"

## 1. 问题定义

迭代 1/2 解决了"入口重复"与"决策负担"，但信息架构仍有三层混乱：

1. **模式不可见不可控**：润色/回复模式由内部规则推断（style 是否为 reply、是否有屏幕分析），只在标题栏一个小徽章里被动显示——用户不知道自己处于什么模式，更无法主动切换。
2. **两条流水线无解释**：回复模式走"识别上下文 → 草稿 + 意图按钮"两段式，润色模式走直接流式改写。差异本身合理（改写我的文字 vs 替我想回复），但没有任何界面语言告诉用户。
3. **话术库衔接不可感知**：参考生成后弹层关闭直接出结果，用户不知道"模板用了、用在哪"。

## 2. 定稿的信息架构（三层心智模型）

```
第一层：工作模式（我在做什么）      —— 标题栏分段开关，始终可见可切换
   ✍️ 润色 = 改写我自己的文字
   💬 回复 = 把原文当作对方消息，帮我想一条回复
第二层：处理方式（谁来写、按什么标准）—— 仅润色模式显示
   ✨ 智能(默认，AI 自动) / 7 风格 / 领域专家 / 并行对比
素材层：📚 话术库（独立任务，两种模式都可用）
   复制模板 = 直接拿走用
   参考生成 = 以你的原文为素材、按模板结构交给 AI 改写（toast 反馈已用哪个模板）
```

**模式规则表**：

| | ✍️ 润色模式 | 💬 回复模式 |
|---|---|---|
| 进入方式 | 分段开关 / AI 划词识别 | 分段开关 / AI 划词识别 / 截图回复快捷键 |
| 界面元素 | 方式下拉 + 话术库 + 补充要求 | 模式说明行 + 对话上下文卡(如有) + 语气意图 chips + 话术库 |
| 生成管线 | 直接流式改写 | 两段式：理解上下文 → 草稿 + 意图按钮 → 点击精修 |
| 处理方式(风格/专家) | 适用 | 不适用（回复有自己的语气体系） |

## 3. 实现改动

| 文件 | 改动 |
|---|---|
| `desktop/src/App.tsx` | 标题栏徽章升级为「✍️ 润色 / 💬 回复」分段开关（`handleSwitchToPolish/ToReply`，切回润色恢复最近风格，回复模式把原文当对方消息重新起草）；「参考生成」增加 toast「已按『XX』模板参考生成」 |
| `shared/components/PolishPanel.tsx` | 方式下拉仅在润色模式显示（回复模式回归独立标签体系）；回复模式新增一行说明"AI 把上方原文当作对方发来的消息…" |

## 4. 验证记录（实机）

- 标题栏分段开关：当前模式高亮、点击即切换，切换后自动按新模式重新生成 ✓
- 回复模式：说明行清晰展示"把原文当对方消息想回复"，语气标签保留、方式下拉隐藏 ✓
- 润色模式：方式下拉（✨ 智能）回归、补充要求占位符正确 ✓

- 静态：tsc ×2、vitest 678/678、双端 build ✓

## 5. 定稿的产品叙事（对用户的一句话）

> **划什么，润什么；跟谁聊天，帮你回。AI 默认全包，想换口径点一下方式，需要现成话术点话术库。**

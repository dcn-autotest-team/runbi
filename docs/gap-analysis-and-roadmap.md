# 润笔 (Runbi) 易用性与核心竞争力缺陷分析及迭代建议书
> **文档定位**：面向技术团队与协同开发（Zcode）的专项改进指南
>
> **编写时间**：2026-08-30（v2，按代码现状逐条校准）
>
> **版本基准**：Runbi Desktop v1.0.3（话术库 / 专家库 / 多专家并行 / 行业包 / 双主题等已计入）

---

## Executive Summary（执行概要）

润笔（Runbi）当前已完成了"系统级全局划词监听 → 悬浮呼出 → 双模式 AI 自动判别 → 多风格流式润色 → 原地无污染安全贴回（失败自动落剪贴板）"的 **核心交互闭环**，并在 Windows 平台上卡住了一个绝佳的生态位（PopClip / Bob 仅局限于 macOS，国内通用 AI 助手大多锁死在浏览器或输入法内）。此外，本轮迭代已补齐三块重资产：**1480 条场景话术模板库**、**277 位行业专家人格库（支持多专家并行对比）**、**5 个行业场景包（关键词自动识别 + 意图芯片）**。

然而，若以**商业化交付、极高口碑留存、以及对抗大厂（Raycast Windows、豆包、输入法内置 AI）侵蚀**的标准来审视，润笔目前存在两个维度的欠缺：

1. **易用性（Usability）**：新用户在"BYOK API Key 配置门槛"上仍面临断崖式流失；"划词全量卡片突然弹窗"仍存在侵入式打扰。
2. **核心竞争力（Moat）**：缺少**用户个人语言风格沉淀（词库 / 样本学风）**、宿主应用感知只做到"模式判定"未做到"细粒度风格注入"、垂直高溢价深水区（公文 / 合同审查 / 学术 LaTeX）尚未挖掘。

> **v2 修订说明**：v1 中"场景微意图预设缺失""贴回失败静默失败""Ollama 无支持"等判断已与代码现状不符（详见「〇、现状基线」），本版逐条重新校准了问题现状与优先级，避免重复造轮子。

## 一、易用性欠缺（Usability & User Experience Gaps）

### 缺陷 1：BYOK（自备 API Key）机制筑起极高门槛，90% 普通用户流失
- **优先级**：`P0（最高）`
- **问题现状（v2 核实，仍成立）**：
  - 新用户未配置 DeepSeek/OpenAI API Key 时，只能体验 Mock 演示数据（`App.tsx` 中 "Offline / Mock fallback" 分支）；
  - 真实的非程序员用户（行政、文员、学生、律师、销售）几乎完全不知道如何去 DeepSeek 开放平台注册实名、充值、生成 `sk-xxxx` 密钥以及配置端点；他们会误以为软件是坏的或直接卸载。
  - 现有 `OnboardingView` 三步引导只解决"看懂"，不解决"用上"——没有 Key 依然无法产生一次真实润色。
- **改进方案（交付给 Zcode）**：
  1. **开箱赠送免配置体验额度（Cloud Proxy Trial）**：
     - 后端设立一个极轻量的官方 Token 代理中转服务；
     - 新设备安装后直接赠送 **10 万 Token（约可润色 300 次）**，用户无需填写任何配置，首次启动划词即可体验完整闭环；
     - 额度耗尽后，弹窗提供友好指引："继续使用：① 填入个人自备 Key（永久免费）；② 扫码获取更多点数"。
  2. **国内主流大模型「一键 OAuth / 扫码免配 Key」接入**：
     - 支持微信扫码或国内平台（如智谱、Kimi、通义千问）的一键快捷授权，消灭复杂的 Base URL 与密码框心智。

---

### 缺陷 2：划词直接弹出完整大卡片，存在视觉侵入与误触打扰
- **优先级**：`P0（最高）`
- **问题现状（v2 核实，仍成立）**：
  - 设置项"划词/复制后自动唤起"开启后，用户只要在屏幕上拖选一段文字（哪怕只是想复制或看看字数），完整润色面板就会立刻弹出覆盖视线；
  - 这种沉重感会让高频划词用户感到烦躁（类似早期金山词霸划词翻译误触），导致很多用户直接关掉划词监听，退化为纯快捷键唤醒，大幅削弱产品黏性。
- **改进方案（交付给 Zcode）**：
  1. **轻重分层的「微胶囊（Action Pill / Mini Capsule）」交互（对标 PopClip/Bob）**：
     - 鼠标划选抬起后，光标右上角仅浮现一个高度 26px、半透明圆角磨砂的 **微型动作胶囊条**（包含 3 个极简图标：`✨ 润色` / `💬 智能回复` / `📋 复制`）；
     - 鼠标若未移向胶囊并在 1.2 秒后移开，胶囊静默淡出，**零打扰**；
     - 用户若点击胶囊或按下热键，再平滑展开为现有的完整大面板；
  2. **双击选词防误触过滤**：
     - 选中文本字数 ≤ 2 个汉字或 4 个字母时，默认不触发胶囊，避免双击单词查词频繁打扰。

---

### 缺陷 3：特殊宿主应用贴回失败的反馈与兜底（v2：大部分已解决，仅剩打磨）
- **优先级**：`P2（中，v2 从 P1 下调）`
- **问题现状（v2 核实，已大幅改善）**：
  - ~~面板直接关闭，宿主应用中文字没有改变，用户以为软件故障~~ → 现状：Rust 贴回失败时自动复制到剪贴板，面板保持打开，Toast 明示"贴回失败，已复制到剪贴板，Ctrl+V 粘贴即可"（3.5 秒）；剪贴板恢复未确认时另有 5 秒提示"未确认目标应用已接收；结果暂留剪贴板，可按 Ctrl+V 重试"。
- **残余 gap 与打磨方向**：
  1. Toast 3.5 秒即逝，特殊宿主（安全沙箱、只读窗口、未聚焦输入框的 Electron 应用）下用户可能错过；可升级为**常驻右下角小浮条**（含"重试贴回 / 打开面板"按钮，手动关闭）；
  2. 贴回前**可写性预探测**（窗口样式 / 输入焦点检查），把"事后道歉"提前为"事前分流"：预判不可写时直接走剪贴板路径并说明原因。

---

### 缺陷 4：润色侧缺少「即拿即用的高频意图芯片」（v2：回复侧已覆盖，润色侧是残余 gap）
- **优先级**：`P1（高）`
- **问题现状（v2 重新校准）**：
  - 已具备：7 种宏观风格（通用润色/学术规范/职场商务/文采飞扬/精简提炼/地道英文/智能回复）；**行业包 `intents` 意图芯片**（如律所包的"婉拒议价""售后安抚"）；**用户自定义快捷动作** `CustomAction`（名称+Prompt，一键 chip）；**1480 条话术模板库**（整段模板，按场景选用）。
  - 残余 gap：三者都覆盖不了"润色模式下的通用高频微意图"——`CustomAction` 要求用户自己会写 Prompt（恰恰是目标用户不会的），话术库是整段模板而非"在我这段话上叠加意图"，行业包芯片只在命中对应行业时出现。用户仍需在自定义指令框反复打："怎么委婉拒绝借钱？""怎么催交付但显得尊重？""怎么去掉 AI 味？""怎么转成周报话术？"
- **改进方案（交付给 Zcode）**：
  1. **内置通用高频意图芯片组（Quick Intent Chips）**：
     - 在润色面板输入区旁增加一组可折叠胶囊：`[委婉推脱]` · `[礼貌催促]` · `[降重/去AI味]` · `[向上汇报]` · `[分点提炼]`；
     - 点击即在当前风格上叠加意图（复用行业包 `intents` 的注入通道，无需新机制）；
     - 与 `CustomAction` 合并渲染：内置芯片在前、用户自定义在后（`PolishPanel.tsx` 已有 merged quickTags 逻辑，扩展即可）。

## 二、核心竞争力欠缺（Core Competitiveness & Moat Gaps）

> **战略核心命题**：如果明天 Raycast Windows 完善了中文划词，或者微软 Edge / 微信输入法内置了 AI 润色，**用户为什么依然非用润笔不可？**

### 缺陷 5：缺少「个人文风与专属词库学习」（消灭 AI 味的最深护城河）
- **优先级**：`P0（绝对核心）`
- **问题现状（v2 核实，仍成立）**：
  - 现有最接近的能力仅是**硬编码广告法极限词检测**（`bannedWords.ts`，只警示不替换、不可自定义）；
  - 没有 Glossary 词汇映射、没有用户自定义禁用词、没有文风样本学习。市面上所有 AI 润色工具输出都带"AI 味 / 机器翻译感"，谁先解决谁赢。
- **改进方案（交付给 Zcode）**：
  1. **专属词汇与替换规则库（Glossary & Rulebook）**：
     - 允许用户在设置中自定义词汇映射与禁忌词：
       - *示例规则 1*："把'用户'全部称为'客户/同仁'"；
       - *示例规则 2*："遇到缩写'DCN'，绝不展开翻译"；
       - *示例规则 3*："禁止使用'首先/其次/综上所述'等教条副词"；
     - 将规则编译为 System Prompt 的硬性约束层（Hard Constraints）；现有 `bannedWords` 检测可升级为"用户词表 + 内置广告法词表"双层，警示与改写联动。
  2. **样本学风（Few-Shot Style Mimicry）**：
     - 提供"我的风格标杆"输入框，允许用户粘贴 2~3 篇自己过去写的最满意的微信对话或邮件；
     - 模型自动分析用户的断句习惯、常用代词、标点风格（如喜不喜欢用空格、语气温和度），润色输出**像用户自己手写的一样**，彻底消灭 AI 味。

---

### 缺陷 6：宿主应用感知只到「模式判定」，未到「细粒度风格注入」
- **优先级**：`P1（核心壁垒）`
- **问题现状（v2 重新校准——底座已通，差最后一层）**：
  - 已具备：Rust 端 `GetForegroundWindow` 已把 `sourceApp` / 窗口标题送进 `classifyContext`，用于决定"回复 vs 润色 vs 翻译 vs 学术 vs 商务"模式与风格；`detectIndustryPack` 按窗口标题与选中文本自动命中行业包。**数据链路全通，缺的只是 per-app 的 Prompt 级风格注入。**
  - 残余 gap：同一判定结果下，微信里和 Word 里的输出质感仍无差异——所有网页插件和通用助手正是这样，一套输出走天下。
- **改进方案（交付给 Zcode）**（在现有 sourceApp 管线上加一层 Prompt 附注即可，不需要新的感知基础设施）：
  1. **基于前景进程名的细粒度风格注入**：
     - `WeChat.exe` / `DingTalk.exe` / `Feishu.exe` → 短句、口语化、高情商、带人情味；
     - `WINWORD.EXE` / `wps.exe` → 规范长句、书面语、严格书面标点；
     - `Code.exe` (VS Code) / `devenv.exe` → 代码注释润色、驼峰命名建议、英文 commit message 规范；
     - `OUTLOOK.EXE` / `Foxmail.exe` → 自动追加邮件开头问候与结尾祝颂语。
  2. **实现位置**：扩展 `shared/core/context.ts` 的模式判定结果（或新建 app-style 映射表），把 app 风格附注与 `sceneHint` 同一通道注入 Prompt 上下文元数据。

---

### 缺陷 7：本地离线模型缺「零配置探测」——离线即正义（v2：provider 已内置，差自动发现）
- **优先级**：`P2（安全与合规壁垒，v2 从 P1 下调：手动配置路径已通）`
- **战略价值**：大厂云端助手永远不可能向军工、涉密国企、金融券商、核心研发人员证明"你的内网代码和机密合同没上云"。**离线即正义。**
- **问题现状（v2 核实）**：Ollama 已是内置 provider（OpenAI 兼容 `localhost:11434/v1`），但用户仍需自己知道"什么是 Ollama、端口是多少"并手动选择；LM Studio 等未预设。
- **改进方案（交付给 Zcode）**：
  1. **本地模型一键探测（Zero-config Local Detection）**：
     - 启动时静默探测 `http://127.0.0.1:11434`（Ollama）、`http://localhost:1234`（LM Studio）等常见端点；
     - 探测成功则 provider 下拉自动亮起绿灯并拉取已装模型清单：`🟢 本地已就绪: deepseek-r1:8b / qwen2.5:7b`；
     - 用户点击即连，**零配置、零网络流量、100% 物理离线可用**。

---

### 缺陷 8：垂直高溢价专业场景（公文 / 法律合同 / 学术论文）未做深水区挖掘
- **优先级**：`P2（商业变现壁垒）`
- **问题现状（v2 核实，仍成立）**：
  - `legal` 行业包只覆盖"律师微信接待话术"，**不是**合同严密性审查；学术只有 `academic` 宏观风格，没有 LaTeX 语法保护；公文无任何专属能力。
  - 战略价值不变：通用润色只能卖几十块钱，体制内公文校对、律所合同审查可以卖数千元企业坐席。
- **改进方案（交付给 Zcode）**：
  1. **党政公文合规校对模式**：
     - 内置国家标准《党政机关公文格式》（GB/T 9704-2012）规范；
     - 严格排查政治性表述错漏、禁用词、领导人排序、特定公文动词搭配（"贯彻落实"、"协同推进"）；
  2. **法律合同严密性审查模式**：
     - 检查义务条款中的"应当"与"可以"、违约金上限模糊表述、争议管辖条款遗漏；
  3. **学术 SCI LaTeX 保护模式**：
     - 遇到 `$math$`、`\cite{}`、`\ref{}` 等 LaTeX 语法标记时自动锁定不可篡改，仅润色周围自然语言。

## 三、Zcode 执行路线图与里程碑拆解（Roadmap v2）

按 v2 校准后的优先级重排三个敏捷迭代冲刺（已完成项已移出，含 v1 未提及但已落地的基线）：

```
Sprint 1: 体验降门槛与防打扰 (易用性破局)
├── 1. 免费试用 Token 中转代理通道 (缺陷1, P0)
├── 2. 划词 Mini Capsule 微胶囊悬浮条 + 双击防误触 (缺陷2, P0)
└── 3. 内置通用高频意图芯片组，与 CustomAction 合并渲染 (缺陷4, P1)

Sprint 2: 风格护城河与个性化 (消灭 AI 味)
├── 1. 个人专属词库与禁忌词规则库 (Glossary & Rulebook) (缺陷5, P0)
├── 2. 少样本个性文风学习 (Few-Shot Prompt) (缺陷5, P0)
└── 3. 本地 Ollama / LM Studio 零配置探测 + 绿灯直连 (缺陷7, P2)

Sprint 3: 宿主细粒度感知与垂直套件 (商业变现)
├── 1. per-app 细粒度风格注入 (微信/Word/VS Code/邮件) (缺陷6, P1)
├── 2. 公文规范 + 学术 LaTeX 保护引擎 (缺陷8, P2)
└── 3. 贴回失败常驻浮条 + 可写性预探测打磨 (缺陷3, P2)
```

**执行提醒（复用清单）**：意图芯片复用行业包 `intents` 注入通道与 `PolishPanel` quickTags 合并逻辑；per-app 风格注入复用 `sourceApp` 管线与 `sceneHint` 注入通道；词库规则复用 `bannedWords` 检测警示框架；贴回兜底复用 `TauriTextReplacer` 的 `fallbackCopied` 状态。不要新建平行机制。

## 四、自查验收指标（Acceptance Criteria）

1. **新用户转化率**：非技术用户初次下载打开，在不输入任何 API Key 的情况下，能在 10 秒内成功完成第一次真实划词润色。
2. **驻留静默度**：日常文字阅读与鼠标划选时，误触率降低 80% 以上（依靠 26px 微胶囊、1.2 秒移开自动隐退与短选区过滤）。

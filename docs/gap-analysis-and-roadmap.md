# 润笔 (Runbi) 易用性与核心竞争力缺陷分析及迭代建议书
> **文档定位**：面向技术团队与协同开发（Zcode）的专项改进指南  
> **编写时间**：2026-08-30  
> **版本基准**：Runbi Desktop v1.0.2  

---

## Executive Summary（执行概要）

润笔（Runbi）当前已完成了“系统级全局划词监听 → 悬浮呼出 → 多风格流式润色 → 原地无污染安全贴回”的 **核心交互闭环**，并在 Windows 平台上卡住了一个绝佳的生态位（PopClip / Bob 仅局限于 macOS，国内通用 AI 助手大多锁死在浏览器或输入法内）。

然而，若以**商业化交付、极高口碑留存、以及对抗大厂（Raycast Windows、豆包、输入法内置 AI）侵蚀**的标准来审视，润笔目前存在两个维度的明显欠缺：
1. **易用性（Usability）**：新用户在“BYOK API Key 配置门槛”上面临断崖式流失；在“划词全量卡片突然弹窗”上面临侵入式打扰；在“特殊应用贴回失败”时缺乏直观的状态反馈。
2. **核心竞争力（Moat）**：润色依然偏向“通用的中规中矩 AI 表达”，缺少**用户个人语言风格沉淀**、缺少**宿主应用感知（Word/微信/VSCode 自适应）**、以及缺少**企业/体制内最愿买单的高门槛垂直规范（公文、合同、学术 LaTeX）**。

---

## 一、易用性欠缺（Usability & User Experience Gaps）

### 缺陷 1：BYOK（自备 API Key）机制筑起极高门槛，90% 普通用户流失
- **优先级**：`P0（最高）`
- **问题现状**：
  - 目前新用户下载安装后，如果未配置 DeepSeek/OpenAI API Key，只能体验预设的死数据 Mock 演示；
  - 真实的非程序员用户（行政、文员、学生、律师、销售）几乎完全不知道如何去 DeepSeek 开放平台注册实名、充值、生成 `sk-xxxx` 密钥，以及配置端点；他们会误以为软件是坏的或直接卸载。
- **改进方案（交付给 Zcode）**：
  1. **开箱赠送免配置体验额度（Cloud Proxy Trial）**：
     - 后端设立一个极轻量的官方 Token 代理中转服务；
     - 新设备安装后直接赠送 **10 万 Token（约可润色 300 次）**，用户无需填写任何配置，首次启动划词即可体验飞一般的感觉；
     - 额度耗尽后，弹窗提供友好指引：“继续使用：① 填入个人自备 Key（永久免费）；② 扫码获取更多点数”。
  2. **国内主流大模型「一键 OAuth / 扫码免配 Key」接入**：
     - 支持微信扫码或国内平台（如智谱、Kimi、通义千问）的一键快捷授权，消灭复杂的 Base URL 与密码框心智。

---

### 缺陷 2：划词直接弹出完整大卡片，存在视觉侵入与误触打扰
- **优先级**：`P0（最高）`
- **问题现状**：
  - 目前如果用户开启“划词自动唤起”，用户只要在屏幕上拖选一段文字（哪怕只是想复制或者看看字数），一个宽 560px、高 520px 的完整润色面板就会立刻跳出来覆盖视线；
  - 这种沉重感会让高频划词用户感到烦躁（类似早期金山词霸划词翻译误触），导致很多用户直接关掉划词监听，退化为纯快捷键唤醒，大幅削弱了产品的黏性。
- **改进方案（交付给 Zcode）**：
  1. **轻重分层的「微胶囊（Action Pill / Mini Capsule）」交互（对标 PopClip/Bob）**：
     - 鼠标划选抬起后，光标右上角仅浮现一个高度 26px、半透明圆角磨砂的 **微型动作胶囊条**（包含 3 个极简图标：`✨ 润色` / `💬 智能回复` / `📋 复制`）；
     - 鼠标若未移向胶囊并在 1.2 秒后移开，胶囊静默淡出，**零打扰**；
     - 用户若点击胶囊或按下热键，再平滑展开为现有的完整大面板；
  2. **双击选词防误触过滤**：
     - 选中文本字数 ≤ 2 个汉字或 4 个字母时，默认不触发胶囊，避免双击单词查词频繁打扰。

---

### 缺陷 3：特殊宿主应用贴回失败时的静默状态与反馈缺失
- **优先级**：`P1（高）`
- **问题现状**：
  - 润笔核心特色是“回车贴回目标应用”。但在某些特殊环境下（如未聚焦输入框的 Electron 应用、某些安全防护沙箱软件、只读窗口、全屏终端控制台），Windows `SendInput` 模拟粘贴无法生效；
  - 此时面板直接关闭，宿主应用中文字没有改变，用户会以为软件故障，感到沮丧。
- **改进方案（交付给 Zcode）**：
  1. **贴回检测与智能容错提示**：
     - 当检测到贴回目标窗口未响应或不可写入时，面板平滑收缩为一个右下角小浮条：`未能自动写入当前应用，已为您复制到剪贴板，请按 Ctrl+V 手动粘贴`；
     - 并在屏幕中心弹出轻微通知胶囊，确保用户知道文字已安全生成并复制。

---

### 缺陷 4：风格分类偏向抽象宏观，缺少即拿即用的「场景微意图预设」
- **优先级**：`P1（高）`
- **问题现状**：
  - 目前仅有 7 种宏观风格（通用润色、学术规范、职场商务、文采飞扬、精简提炼、地道英文、智能回复）；
  - 但用户的实际日常痛点往往极其具体：
    - “怎么委婉拒绝借钱/拒绝无理需求？”
    - “怎么催促对方快点交付，但语气还得显得很尊重？”
    - “怎么把口语转成大厂周报汇报话术？”
    - “怎么给外国教授写请教邮件？”
  - 用户目前必须在自定义指令输入框里反复打长句子。
- **改进方案（交付给 Zcode）**：
  1. **高频场景意图芯片（Quick Intent Chips）**：
     - 在润色面板输入框上方或风格切换侧边，增加一组可折叠的高频微意图胶囊：
       - `[委婉推脱]` · `[礼貌催促]` · `[降重/去AI味]` · `[向上汇报]` · `[分点提炼]`
     - 用户点击芯片即可在当前风格上叠加具体意图，1 秒直达预期文采。

## 二、核心竞争力欠缺（Core Competitiveness & Moat Gaps）

> **战略核心命题**：如果明天 Raycast Windows 完善了中文划词，或者微软 Edge / 微信输入法内置了 AI 润色，**用户为什么依然非用润笔不可？**

### 缺陷 5：缺少「个人文风与专属词库学习」（消灭 AI 味的最深护城河）
- **优先级**：`P0（绝对核心）`
- **竞品痛点**：目前市面上所有的 AI 润色工具，生成出来的文字都带着一股浓浓的“AI 味 / 机器翻译感”，套路化严重；
- **改进方案（交付给 Zcode）**：
  1. **专属词汇与替换规则库（Glossary & Rulebook）**：
     - 允许用户在设置中自定义词汇映射与禁忌词：
       - *示例规则 1*：“把‘用户’全部称为‘客户/同仁’”；
       - *示例规则 2*：“遇到缩写‘DCN’，绝不展开翻译”；
       - *示例规则 3*：“禁止使用‘首先/其次/综上所述’等教条副词”；
     - 将规则在本地编译为 System Prompt 的硬性约束约束层（Hard Constraints）。
  2. **样本学风（Few-Shot Style Mimicry）**：
     - 提供一个“我的风格标杆”输入框，允许用户粘贴 2~3 篇自己过去写的最满意的微信对话或邮件；
     - 模型自动分析用户的断句习惯、常用代词、标点风格（如喜不喜欢用空格、语气的温和度），润色输出的文字**像用户自己手写出来的一样**，彻底消灭 AI 味。

---

### 缺陷 6：缺少「宿主应用感知（Context-Aware Adaptation）」
- **优先级**：`P1（核心壁垒）`
- **竞品痛点**：所有网页插件和通用助手完全不知道用户当前在干什么，只会给一套一模一样的输出。
- **改进方案（交付给 Zcode）**：
  1. **基于前景进程名的智能环境适配（Native OS 物理优势）**：
     - 当检测到当前前台软件是 **`WeChat.exe` / `DingTalk.exe` / `Feishu.exe`**：
       - 自动倾向于短句、口语化、高情商回复、适当带点人情味；
     - 当检测到当前前台软件是 **`WINWORD.EXE` / `wps.exe`**：
       - 自动倾向于规范长句、书面语、严格书面标点；
     - 当检测到当前前台软件是 **`Code.exe` (VS Code) / `devenv.exe`**：
       - 自动倾向于代码注释润色、变量驼峰命名建议、英文 commit message 规范；
     - 当检测到前台是 **`OUTLOOK.EXE` / `Foxmail.exe`**：
       - 自动追加邮件开头问候与结尾祝颂语。
  2. **技术实现**：
     - 利用 Rust 端已有 `GetForegroundWindow` / `GetWindowThreadProcessId`，直接注入进程标记到 Prompt 的上下文元数据中。

---

### 缺陷 7：对本地离线大模型（Ollama / LM Studio）缺乏开箱即用支持
- **优先级**：`P1（安全与合规壁垒）`
- **战略价值**：大厂云端助手永远不可能向军工、涉密国企、金融券商、核心研发人员证明“你的内网代码和机密合同没上云”。**离线即正义**。
- **改进方案（交付给 Zcode）**：
  1. **本地模型一键探测（Zero-config Local Detection）**：
     - 启动时自动探测 `http://127.0.0.1:11434`（Ollama）或 `http://localhost:1234`（LM Studio）；
     - 若探测成功，下拉菜单中自动亮起绿灯：`🟢 本地已就绪: deepseek-r1:8b / qwen2.5:7b`；
     - 用户点击即连，**零配置、零网络流量、100% 物理离线可用**。

---

### 缺陷 8：垂直高溢价专业场景（公文 / 法律合同 / 学术论文）未做深水区挖掘
- **优先级**：`P2（商业变现壁垒）`
- **战略价值**：通用润色只能卖几十块钱，但体制内公文校对、律所合同审查可以卖数千元企业坐席。
- **改进方案（交付给 Zcode）**：
  1. **党政公文合规校对模式**：
     - 内置国家标准《党政机关公文格式》（GB/T 9704-2012）规范；
     - 严格排查政治性表述错漏、禁用词、领导人排序、特定公文动词搭配（“贯彻落实”、“协同推进”）；
  2. **法律合同严密性审查模式**：
     - 检查义务条款中的“应当”与“可以”、违约金上限模糊表述、争议管辖条款遗漏；
  3. **学术 SCI LaTeX 保护模式**：
     - 遇到 `$math$`、`\cite{}`、`\ref{}` 等 LaTeX 语法标记时，自动锁定绝对不可篡改，仅润色周围自然语言。

## 三、Zcode 执行路线图与里程碑拆解（Roadmap）

为了让 Zcode 能够高效率、不走弯路地逐步推进，建议将上述改进分为三个敏捷迭代冲刺：

```
Sprint 1: 体验降门槛与防打扰 (易用性破局)
├── 1. 划词 Mini Capsule (微胶囊悬浮条)
├── 2. 免费试用 Token 中转代理通道
└── 3. 本地 Ollama 自动探测与一键直连

Sprint 2: 风格护城河与个性化 (消灭 AI 味)
├── 1. 个人专属词库与禁忌词规则配置
├── 2. 少样本个性文风学习 (Few-Shot Prompt)
└── 3. 高频意图微动作芯片 (委婉拒绝/礼貌催促/去AI味)

Sprint 3: 原生宿主感知与垂直套件 (商业变现)
├── 1. 宿主应用感知 (微信/Word/VS Code 自动适配风格)
├── 2. 公文规范与学术 LaTeX 代码块保护引擎
└── 3. 特殊应用贴回失败平滑兜底浮条
```

## 四、自查验收指标（Acceptance Criteria）

1. **新用户转化率**：非技术用户初次下载打开，在不输入任何 API Key 的情况下，能在 10 秒内成功完成第一次真实划词润色。
2. **驻留静默度**：日常文字阅读与鼠标划选时，误触率降低 80% 以上（依靠 24px 微胶囊与 1.2 秒移开自动隐退）。
3. **文采满意度**：配置个人风格样本后，盲测润色结果与用户本人以往邮件相比，AI 违和感显著下降。
4. **离线可用度**：在断网拔掉网线环境下，连接本地 Ollama 模型，划词润色与原地替换正常工作。
